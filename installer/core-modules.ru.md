# Модули PL

Гид для PL 0.8.5. **Каталог модулей** нужен для установки и подключения сервисов. В разделе **Подключённые модули** можно открыть каждый сервис, проверить его состояние и изменить настройки. Для установки и настройки модулей войдите в PL с правами администратора.

## Установка и первый запуск

1. Откройте **Каталог модулей**. На карточке сервиса выберите **Установить на хост**, чтобы запустить его на сервере PL, или **Подключить существующий**, если сервис уже работает на другом сервере. Для подключения укажите адрес и заполните поля, которые запрашивает PL.
2. Введите название экземпляра и нажмите **Установить** или **Подключить**. Кнопка **Установить несколько** позволяет выбрать сразу несколько локальных модулей. PL загрузит пакеты и поставит операции в очередь.
3. Откройте **Подключённые модули**. Когда карточка покажет **Работает**, откройте сервис из неё. Если вы перешли раньше, дождитесь готовности на странице запуска.

Для локальных Grafana, NetMap и Wiki откройте карточку модуля и нажмите **Первоначальный вход**. Там PL показывает данные для входа в Grafana, NetBox и Gitea либо BookStack. Для уже работающего внешнего сервиса используйте его учётную запись, если он запрашивает вход. Forms и Doska открываются в текущей сессии PL.

Кнопка **Установить на хост** появляется, когда каталог предлагает пакет для вашей версии PL и архитектуры сервера. Если сервер ходит в GitHub через прокси, задайте его в **Настройки → Прокси для загрузок** и нажмите **Проверить доступ к GitHub**. [Установка PL и настройка прокси](README.public.ru.md).

## Первые действия в каждом модуле

### Почта

На карточке **Почта** выберите **Подключить существующий** и раскройте **Как подключить Mailcow**. После подключения откройте **Управлять почтой** и проверьте время последнего успешного сбора. На странице видны почтовые ящики, очередь, службы, хранилище и данные Rspamd.

### Alertmanager

1. Из карточки откройте **Уведомления** и нажмите **Добавить получателя**. Выберите канал, например **Email · SMTP** или **Telegram**, и заполните его настройки.
2. Задайте, какие уведомления отправлять получателю, и выберите оформление сообщений. Примените конфигурацию и проверьте, что получатель появился в карточке действующей конфигурации.
3. Для настроенного email-получателя откройте редактор шаблона. В блоке **Контрольная доставка** отправьте тревогу, затем восстановление и проверьте оба письма в ящике получателя.

### Xray

1. Откройте **Управлять прокси**. В редакторе конфигурации настройте входящее SOCKS- или HTTP-подключение и выберите, через какой сервер выпускать трафик.
2. Нажмите **Проверить конфигурацию**, затем **Применить**. Укажите адрес и порт входа в приложении, которое будет пользоваться прокси, и откройте через него нужный ресурс. Счётчики на странице управления покажут трафик этого подключения.

### Prometheus

1. У локального Prometheus откройте **Мониторинг**, перейдите к конфигурации и нажмите **Добавить задание**. Задайте имя и адрес цели, с которой Prometheus будет получать метрики.
2. Проверьте и примените конфигурацию. После первого опроса найдите адрес в **Текущие цели сбора** и проверьте, что рядом показано **Сбор успешен**. Для подключённого Prometheus этот список показывает результаты сбора на его сервере.

### Wayline

1. Нажмите **Открыть Wayline**, укажите IP-адрес или имя хоста и запустите проверку маршрута.
2. Посмотрите, через какие узлы проходит маршрут, и где Wayline измерил задержки или потери пакетов.

### File Auditor

1. Подключите уже работающий File Auditor из каталога и откройте его карточку в **Подключённые модули**.
2. Нажмите **Открыть File Auditor** и выберите готовый отчёт. В нём можно посмотреть проверенные папки и найденные ошибки структуры.

### Grafana

1. Откройте Grafana и войдите с данными из **Первоначальный вход**. Добавьте Prometheus как источник данных и укажите адрес, доступный с сервера Grafana.
2. Откройте **Explore** и выполните запрос `up`. Если у Prometheus есть цели, Grafana покажет результат их последнего опроса.

### Forms

1. Откройте Forms, создайте опрос и добавьте первый вопрос.
2. Опубликуйте опрос и отправьте пробный ответ по его ссылке. Вернитесь в Forms и откройте результаты, чтобы увидеть ответ.

### Doska

1. Откройте Doska и создайте проект. На доске проекта добавьте задачу с названием и описанием.
2. Переместите задачу в другую колонку и откройте её карточку. В ней будет виден новый статус.

### SFTPGo

1. Из карточки откройте **Управлять SFTPGo**. На вкладке **Учётные записи** добавьте файловую учётную запись с паролем и задайте доступ к папке.
2. Войдите через **Открыть файлы** с этим логином и паролем и загрузите пробный файл. Для SFTP-клиента используйте адрес и порт из вкладки **Подключение SFTP**. В SFTP-клиенте можно также войти по SSH-ключу. По умолчанию SFTP доступен с хоста PL, веб-доступ идёт через PL.

### NetMap

1. Из карточки NetMap откройте **Настроить сети**. В разделе **Сети** нажмите **Добавить сеть**, укажите имя и диапазон в формате CIDR, например `192.0.2.0/24`. После сохранения начнётся первая проверка. Кнопка **Запустить проверку** запускает её повторно.
2. Если для найденного устройства нужен подробный опрос, нажмите **Настроить доступ** и назначьте профиль. В **Доступ и конфигурации** можно подготовить отдельные профили для роутера, коммутатора и сервера. Подберите способ сбора под устройство, например SNMP для интерфейсов, SSH для Linux и сетевого оборудования или WinRM для Windows.
3. Откройте карту и проверьте, какие устройства и связи появились. Чтобы указать, на каком гипервизоре работает виртуальная машина, откройте её карточку и нажмите **Назначить хост в NetBox**. В NetBox выберите устройство в поле **Device** и сохраните запись. После обновления карты хост появится в карточке ВМ, а между узлами будет связь **Размещение ВМ**.

Чтобы убрать диапазон из опроса, откройте **Сети**, нажмите **Удалить сеть** рядом с ним и подтвердите. Эта команда удаляет диапазон и результаты его проверок. Устройства в NetBox и история конфигураций сохраняются.

### Wiki

1. Нажмите **Открыть Wiki** и войдите с данными из **Первоначальный вход** или со своей учётной записью BookStack для уже подключённого сервиса.
2. Создайте книгу и первую страницу. Сохраните страницу и откройте её из оглавления книги.

## Состояние и ошибки

На карточке в **Подключённые модули** видно состояние сервиса и время последней проверки. При статусе **Данные устарели** посмотрите **Последний успех**, чтобы понять, когда PL последний раз получила данные. Чтобы повторить проверку, откройте **Действия → Проверить**. Если установка или обновление завершились с ошибкой, откройте запись в **События → Операции**.

## Обновление модулей

Откройте **Настройки → Обновления** и нажмите **Проверить обновления модулей**. У модуля с доступным пакетом появится кнопка **Обновить** с его названием. Кнопка **Обновить всё** сначала ставит доступное обновление PL, затем последовательно обновляет установленные модули, для которых есть совместимые пакеты. Откройте модуль после завершения операции и проверьте, что он работает. Для SFTPGo предусмотрено отдельное окно обслуживания с закрытым файловым доступом. Подключённые внешние сервисы обновляйте на их серверах. [Порядок обновления](delivery.ru.md#обновление-из-интерфейса).

## Отключение и удаление

- **Действия → Отключить** останавливает локальный экземпляр или проверки внешнего сервиса. Данные сохраняются. Чтобы продолжить работу, нажмите **Включить**.
- **Действия → Удалить** запрашивает название экземпляра для подтверждения. Удаление локального экземпляра стирает его данные на хосте PL. Перед удалением сохраните нужные данные. Удаление подключения внешнего сервиса убирает его из PL, а сервис и его данные остаются на своём сервере.
