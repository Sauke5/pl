# Установка PL

Установщик загружает ядро PL (API, веб-интерфейс и PostgreSQL). Выбранные модули скачиваются отдельно из интерфейса PL. Начните с установки ядра, затем откройте [руководство по модулям](core-modules.ru.md).

## Быстрый запуск

На Ubuntu или Debian:

```sh
curl -fsSL https://raw.githubusercontent.com/Sauke5/pl/main/installer/get-pl.sh | sudo sh -s -- --production
```

Установщик проверяет подпись стабильного каталога, размер и SHA256 пакета, подготавливает Docker и запускает PL. HTTPS-адрес выбирается автоматически. Чтобы задать свой домен или IP, передайте `--public-url`.

```sh
curl -fsSLo get-pl.sh https://raw.githubusercontent.com/Sauke5/pl/main/installer/get-pl.sh
sudo sh get-pl.sh --production --public-url https://pl.example.test
```

## Первый вход

1. Откройте HTTPS-адрес, который появится в терминале после установки. При первой установке с самоподписанным сертификатом добавьте доверие в браузере. Свой сертификат можно задать в разделе **Настройки → Адрес и сеть**.
2. Войдите как `admin`. Установщик покажет путь к файлу с первоначальным паролем. Для стандартного каталога `/opt/pl` его можно прочитать командой:

   ```sh
   sudo cat /opt/pl/private/initial-admin-password
   ```

3. Смените пароль в PL. При повторном запуске установщик сохраняет текущий пароль и данные. Файл содержит первоначальный пароль.

Для новой рабочей установки указывайте `--production`. Старую установку с коротким первоначальным паролем можно возобновить в исходном режиме и сменить пароль через PL. При ручной установке из пакета можно [задать первоначальный пароль из файла](README.package.ru.md).

## Первая установка через прокси

Укажите прокси дважды. `curl` скачивает `get-pl.sh`, затем скрипт через тот же прокси получает каталог, пакет PL и ключ Docker. Для HTTP CONNECT используйте `http://`, для SOCKS5 с DNS на стороне прокси — `socks5h://`.

```sh
PL_PROXY='socks5h://PROXY_HOST:PORT'
curl -fsSL --proxy "$PL_PROXY" \
  https://raw.githubusercontent.com/Sauke5/pl/main/installer/get-pl.sh \
  | sudo sh -s -- --production --proxy "$PL_PROXY"
```

Если прокси требует логин и пароль, добавьте `--proxy-user` к обеим частям команды.

```sh
curl -fsSL --proxy "$PL_PROXY" --proxy-user 'LOGIN:PASSWORD' \
  https://raw.githubusercontent.com/Sauke5/pl/main/installer/get-pl.sh \
  | sudo sh -s -- --production --proxy "$PL_PROXY" --proxy-user 'LOGIN:PASSWORD'
```

Замените адрес, порт и учётные данные своими. Если Xray уже запущен на сервере установки, можно указать `127.0.0.1` и порт его HTTP/SOCKS5-входа. Системный `apt` использует собственные настройки и должен иметь доступ к репозиториям ОС, а при установке Docker — также к его apt-репозиторию.

Если скрипт уже скачан, параметры для его загрузок можно передать в закрытом файле владельца root с правами `0600`.

```json
{"url":"socks5h://PROXY_HOST:PORT","username":"LOGIN","password":"PASSWORD"}
```

Запуск с таким файлом — `sudo sh get-pl.sh --production --proxy-file /root/pl-proxy.json`.

## Модули и обновления

Если сервер обращается к GitHub через прокси, после входа откройте **Настройки → Прокси для загрузок**. Выберите внешний HTTP CONNECT или SOCKS5 либо используйте вход уже установленного Xray. Нажмите **Проверить доступ к GitHub**, затем **Сохранить**. Этот профиль используется при загрузке обновлений и модулей. Открыть его можно и через **Настройки → Обновления → Настроить доступ к GitHub**.

Откройте **Каталог модулей**, выберите нужную карточку и нажмите **Установить на хост**. Если кнопки нет, нажмите **Проверить каталог**. При ошибке доступа к GitHub проверьте настройки прокси. Для модулей с поддержкой внешнего сервиса карточка предлагает **Подключить существующий**. [Список модулей и настройки](core-modules.ru.md).

В **Настройки → Обновления** нажмите **Проверить обновления**. Здесь можно прочитать, что нового в выпуске, и выбрать обновление PL, отдельного модуля или **Обновить всё**. Общая очередь ставит доступную версию PL первой, затем обновляет совместимые локальные модули по одному. Оставьте вкладку открытой. На время остановки сервисов PL показывает экран с текущим этапом и открывается снова после проверки готовности. При ошибке очередь останавливается. [Порядок обновления и восстановление](delivery.ru.md#обновление-из-интерфейса).

В разделе **Настройки → Адрес и сеть** меняются адрес PL, TLS-сертификат, разрешённые сети и порты источников и CA внешних HTTPS-интеграций. [Руководство по настройкам PL](platform-guide.ru.md).

Ручная диагностика входит в обычный core: ICMP, DNS, PTR, HTTP, TCP, TLS,
проверка выбранных портов и клиент iperf3. Компоненты ICMP подготавливаются
автоматически при установке и обновлении. Ограничения ICMP по IPv4-сетям меняются
в настройках развёртывания. Для измерения скорости на целевом сервере должен
работать iperf3-server; наличие клиента в PL не запускает сервер на проверяемом
устройстве.

## Сборка из исходников

Из корня репозитория с локальным Docker:

```sh
python3 installer/package.py context --output release/generated/pl-source.tar.gz
python3 installer/package.py build --source-archive release/generated/pl-source.tar.gz --version VERSION --output release/generated/pl-VERSION.tar.gz
```

По умолчанию `build` создаёт только core. Дополнительные исходники выбираются флагами `context --with-*`. Отдельный модуль собирается командой `module --module-id MODULE` из context с его исходниками; точные доступные имена и параметры показывает `python3 installer/package.py --help`.

```sh
python3 installer/package.py context --with-forms --output release/generated/pl-forms-source.tar.gz
python3 installer/package.py module --module-id forms --source-archive release/generated/pl-forms-source.tar.gz --version VERSION --output release/generated/pl-forms-VERSION.tar.gz
```

Артефакты immutable: существующий version/file не перезаписывается другой сборкой. Публичный каталог подписывается отдельным release key; приватный ключ не входит в исходники и образы. Смена PostgreSQL major и несовместимого протокола модулей требует отдельного перехода.

Размеры ядра, модулей и исходников указаны в файлах [выпуска PL](https://github.com/Sauke5/pl/releases/latest). Ядро содержит готовые Docker-образы. Архив исходников содержит отобранный код и его manifest.

## Счётчик установок

После запуска PL отправляет счётчику по HTTPS сгенерированный идентификатор установки и её версию. Счётчик хранит одну запись на идентификатор и обновляет версию в этой записи при следующем отчёте.

## Проверки и восстановление

```sh
python3 -m unittest discover -s installer/tests
```

На macOS для canonical-path тестов используйте `TMPDIR=/private/tmp`. Go integration tests требуют отдельную PostgreSQL; frontend и component tests запускаются из соответствующего приложения. Unit tests не подтверждают установку или пользовательский сценарий.

Web upgrade создаёт согласованный snapshot установки, включая данные локальных модулей. При неудаче требуется возвращать и данные, и образы. Отдельная [утилита maintenance](maintenance.ru.md) сохраняет прежний ограниченный контракт backup/restore core и отказывает при локальных модулях; она не заменяет snapshot web upgrade.

Для полной установки с native-модулями предусмотрено [аварийное резервное копирование и восстановление](disaster-recovery.ru.md). `disaster-recovery.py` сохраняет данные, ключи, настройки и нужные образы. Cold restore возвращает ту же установку с прежними root, HTTPS-адресом и installation ID на подготовленном Linux. Архив и его SHA256 храните вне исходного сервера; установленная версия инструмента и руководство находятся в `ROOT/releases/VERSION/`.

Обе standalone-админки, host-agent и Reports доступны как исходные компоненты; они не устанавливаются вместе с core автоматически. Их размещение и доступ задаются для конкретной установки. File Auditor требует отдельной Windows-приёмки службы и сканирования.

Перед публичным экспортом новые выбранные исходники должны быть добавлены в Git index: exporter использует тот же allowlist, что и source builder. `python3 installer/public-export.py` создаёт новый каталог `release/generated/public-pl` с manifest и не переносит историю Git. Отчёт аудита остаётся в `release/private` и не входит в публикуемые файлы.
