# Первые шаги в PL

После установки откройте адрес, который вывел установщик, и войдите как `admin`. При установке с `--production` начальный пароль хранится на сервере в файле `/opt/pl/private/initial-admin-password`. Прочитайте его от имени администратора сервера и смените пароль после входа.

```sh
sudo cat /opt/pl/private/initial-admin-password
```

Путь начинается с выбранного каталога, если при установке передан `--root`. Для установки через прокси, собственного адреса и сертификата откройте [руководство установщика](README.public.ru.md).

## Добавьте первый ресурс

1. В рабочем пространстве нажмите **Добавить ресурс**.
2. Укажите понятное название и адрес. Для веб-сервиса укажите полный URL, по которому его обычно открывают.
3. Сохраните карточку. Найдите её через **Найти ресурс или действие** и проверьте, что ссылка ведёт на нужный сервис.

Если несколько ресурсов составляют один сервис, добавьте их в систему. Группы рабочего пространства помогают собрать часто используемые карточки рядом.

## Проверьте адрес

1. Нажмите **Проверить адрес** в верхней панели. Если ресурс уже есть в каталоге, проверку можно запустить из его карточки.
2. Выберите проверку и укажите цель. Для проверки доступности хоста подойдёт ICMP, для веб-сервиса укажите URL в HTTP, для проверки службы выберите TCP и задайте порт.
3. Нажмите **Запустить проверку** и откройте результат. Сетевой запрос идёт с сервера PL, поэтому результат зависит от его маршрутов и разрешённых диапазонов.

Разрешённые диапазоны проверок и HTTPS-сертификат настраиваются в **Настройки → Адрес и сеть**. Нагрузку на сервер и свободное место на диске можно посмотреть в **Состоянии сервера**.

Раздел **События** содержит изменения и результаты мониторинга. Во вкладке **Операции** можно найти запущенную проверку или задачу установки, её цель и результат. **Аудит** показывает действия пользователей.

## Добавьте корпоративный сертификат доверия

Загрузите корневой сертификат корпоративного центра сертификации один раз, чтобы PL могла подключаться к HTTPS-сервисам с сертификатами этого центра и проверять соединение с Active Directory.

1. Войдите в PL администратором и откройте **Настройки → Адрес и сеть → Сертификаты внешних интеграций**.
2. В поле **Дополнительный CA для интеграций** выберите сертификат в формате PEM. Если нужна цепочка, поместите сертификаты центра в один PEM-файл.
3. Нажмите **Применить параметры**, затем **Проверить и применить**. Дождитесь сообщения **Параметры применены** после краткого перезапуска PL.
4. При подключении сервиса укажите полное DNS-имя, указанное в его сертификате. Например, для HTTPS используйте `https://service.example.com`, если сертификат выпущен на `service.example.com`.

## Выгрузите логи для разбора сбоя

Войдите администратором и откройте **Настройки → Состояние сервера → Экспорт логов**. Выберите период от часа до семи дней и нажмите **Скачать ZIP**. В архив входят доступные Docker-логи ядра и локальных модулей, журналы служб контроллера, обновления и ICMP, состояние установки, а также записи событий, аудита и операций из PostgreSQL.

Начните с `manifest.json`. Он показывает период и результат сбора по каждому источнику, а `host/manifest.json` уточняет фактическое время первой и последней записи в файлах с хоста. Глубина зависит от ротации и истории существующих контейнеров. При чистой установке ядро использует драйвер Docker `local` с тремя файлами по 10 МБ на контейнер. При обновлении сохраняются настройки логирования существующей установки.

Для разбора ошибки запроса найдите `X-Request-ID` в ответе и ищите это значение в `request_id` в логах nginx и API. Запись API содержит код ошибки, если обработчик его вернул. Экспорт отмечается в аудите.

## Настройте вход для команды

В **Настройках** откройте **Локальные пользователи**, чтобы создать отдельные учётные записи. Доступ администратора нужен для установки модулей и управления общими настройками. Параметры паролей и срока сессий собраны в разделе **Пароли и сессии**.

Для Active Directory используйте **Вход через домен**. Укажите полное DNS-имя сервера в адресе и заполните параметры домена. Оставьте поле **Отдельный сертификат для AD** пустым, чтобы использовать общий CA. Если для AD нужен отдельный центр сертификации, вставьте его сертификат или цепочку в формате PEM. Нажмите **Проверить подключение**, сохраните настройки через **Проверить и сохранить** и проверьте вход тестовой доменной учётной записью. Локальный администратор остаётся доступен для входа в PL. [Настройка общего CA](#добавьте-корпоративный-сертификат-доверия)

## Установите нужные модули

Откройте **Каталог модулей** и выберите сервис. Нажмите **Установить на хост**, чтобы запустить его на сервере PL, или **Подключить существующий**, если такой вариант есть у выбранного модуля. Дождитесь готовности и откройте его карточку в **Подключённых модулях**. Данные для входа в сервисы с отдельными учётными записями доступны по кнопке **Первоначальный вход**.

[Гид по модулям](core-modules.ru.md)

## Обновите Платформу

Откройте **Настройки → Обновления** и нажмите **Проверить обновления**. Прочитайте описание версии. **Обновить всё** запускает доступные совместимые шаги по очереди, начиная с PL, если для неё есть новая версия. Если GitHub доступен только через прокси, сначала сохраните и проверьте соединение в разделе **Прокси для загрузок**.
