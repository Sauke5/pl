# PL: установка

Основной core-пакет содержит API, веб-интерфейс и PostgreSQL. Образы модулей
скачиваются отдельно после выбора установки в web PL. Точный состав,
архитектура, версии образов и контрольные суммы указаны в `manifest.json`.
Подключения к внешним системам создаёт администратор после установки.

Установщик запускается от root на поддерживаемом Linux с локальным Docker. Он проверяет платформу, ресурсы, свободные сетевые диапазоны и принадлежность каталогов. При необходимости устанавливает host dependencies. Диски и разделы не форматирует. Минимальный бюджет core — 4 ГиБ usable RAM и 20 ГиБ свободного места; для модулей нужны дополнительные ресурсы.

```sh
sudo sh pl-install-VERSION.sh --check
sudo sh pl-install-VERSION.sh \
  --production \
  --package /path/to/pl-VERSION.tar.gz \
  --root /opt/pl \
  --public-url https://pl.example.invalid \
  --bind-address YOUR_LOCAL_IP \
  --self-signed
```

Замените URL и bind на параметры своего сервера. Минимальный core выбирает
свободный private IPv4 /24 по текущим маршрутам и Docker networks; при необходимости
можно явно передать `--network-cidr CIDR`. Повтор установки сохраняет этот диапазон.
Для собственного сертификата передайте `--tls-cert PATH --tls-key PATH` вместо
`--self-signed`. Клиент должен доверять сертификату. Для online delivery используйте
`--package-url HTTPS_URL --package-sha256 TRUSTED_SHA256`; внешний hash получают по
доверенному каналу релиза.

С `--production` первоначальный вход — `admin` со случайным паролем.
Установщик сообщает путь к файлу `ROOT/private/initial-admin-password` с режимом
0600. Для стандартного root пароль можно прочитать командой
`sudo cat /opt/pl/private/initial-admin-password`; само значение установщик не
печатает. После первого входа смените пароль в PL.

Собственный первоначальный пароль задаётся через `--password-file PATH`:
root-owned файл 0600, не менее 12 байт. Этот параметр имеет приоритет над
генерацией. Значение не передаётся через командную строку или environment.
При повторе seed, хеш и действующий пароль сохраняются, даже если передан
другой password file. Файл seed содержит первоначальный пароль, а не его
актуальное значение после смены в PL.

Без `--production` сохранён прежний режим совместимости `admin / admin`.
Установку с сохранённым коротким seed `--production` отклоняет без замены
credentials; для её возобновления используйте прежний режим.

Пользователи и их роли настраиваются в «Настройки → Пользователи». Модули устанавливаются или подключаются из каталога. БД и API не публикуют host ports; web открывает только выбранный HTTPS endpoint. Сети, данные и credentials принадлежат конкретной установке.

Повтор установки тем же пакетом и с теми же параметрами сохраняет identity и данные.
Обновление выполняется отдельной операцией из настроек PL по доверенному каталогу
релизов. Откат образов не откатывает схему БД. Каталоги `private/`, `state/` и volumes
не входят в распространяемый пакет.

## Ручная проверка ICMP

ICMP входит в обычную поставку PL. Установщик и обновление из web автоматически
подготавливают `hping3` и отдельный host helper. API обращается к нему через закрытый
Unix socket; сетевые capabilities API не выдаются.

По умолчанию администратор проверяет выбранный IPv4-адрес или hostname так же,
как в остальных ручных инструментах. Локальные служебные адреса, multicast и
адреса metadata-сервисов недоступны. Политика внешних интеграций задаётся отдельно.

При необходимости в **Настройки → Развёртывание → ICMP-диагностика** можно выбрать
режим «Только указанные сети» и задать canonical IPv4 CIDR. Пустой список в этом
режиме запрещает все ICMP-цели. Ранее явно настроенные диапазоны сохраняются при
обновлении, включая пустой список. Для первоначальной установки также сохранён
совместимый параметр:

```sh
--icmp-allowed-cidr 10.80.0.0/24 --icmp-allowed-cidr 10.81.0.0/24
```

Это примеры; выберите собственные диапазоны. Проверка запускается вручную,
отправляет 2000 ICMP-пакетов с интервалом 2000 микросекунд; максимум один активный
запуск, 25 секунд и 1 МиБ вывода. Полный вывод доступен в результате проверки.
Периодический ICMP в scheduler не включается.

Для удаления только принадлежащего установке helper:

```sh
sudo python3 /opt/pl/releases/VERSION/bootstrap.py remove-icmp-helper --root /opt/pl
```

Команда проверяет identity и контрольные суммы, останавливает свои units и удаляет только свои файлы. Core и его данные сохраняются; ручной ICMP станет недоступен.

## Состояние и восстановление

```sh
sudo python3 /opt/pl/releases/VERSION/bootstrap.py status --root /opt/pl
```

При ошибке доступны `state/installation.json` и закрытый `private/last-command.log`. Не удаляйте volumes для повторной установки. Для backup используйте `maintenance.py` соответствующей версии и её руководство. Текущий backup contract охватывает core и отказывает при наличии локальных модулей; данные модулей требуют отдельного согласованного плана резервного копирования.

Поддерживаемые версии ОС и архитектура конкретного пакета проверяются установщиком. Список допустимых платформ сам по себе не подтверждает прохождение всех сценариев на каждой из них.
