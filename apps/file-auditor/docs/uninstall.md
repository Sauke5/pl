# Закрытие экземпляра файлового аудитора

Комплект рассчитан на один экземпляр Windows Service `FileStructureAuditor` на выбранном сервере с каталогами `FileStructureAuditor`. Сначала снимите маршрут Платформы, затем удалите локальную службу. Для второго экземпляра повторите процедуру отдельно.

## 1. Снять маршрут Платформы

В репозитории Платформы удалите ссылку на закрываемый экземпляр, его gateway route (`/audit/` или `/audit-arch/`), backend URL, Compose overlay и разрешение исходящего соединения к этому серверу. Проверьте итоговый Compose config и nginx config, примените изменение и убедитесь, что маршрут больше не проксирует запросы к Auditor. Сохраните рабочие маршруты других сервисов и второго экземпляра Auditor.

После остановки gateway удалите принадлежащий закрытому экземпляру файл ключа из настроенного защищённого каталога и проверьте, что он больше не смонтирован в Portal API. Ключ второго экземпляра сохраните. Удалите принадлежащие экземпляру DNS A запись и monitoring target после проверки, что ими не пользуются другие сервисы.

## 2. Удалить службу на Windows

Перед удалением проверьте, что обход завершён и в службе нет активного сканирования. Запустите PowerShell от администратора на целевом сервере из каталога релиза:

```powershell
.\scripts\Uninstall-Auditor.ps1
```

Preview показывает службу, каталоги, число целевых firewall rules и действие с сертификатом. Для сохранения копии укажите новый каталог вне путей Auditor:

```powershell
.\scripts\Uninstall-Auditor.ps1 -Apply -PurgeData -BackupDirectory 'D:\Auditor-backup'
```

Скрипт ограничит права резервной копии до SYSTEM и Administrators, затем остановит и удалит только службу `FileStructureAuditor`, её install/data каталоги (включая SQLite, логи и локальный gateway key) и firewall rules с точными именами. Если копирование завершится ошибкой до удаления службы, скрипт вернёт её в исходное работающее состояние. Резервная копия содержит gateway key; храните её в защищённом месте и удалите вместе с экземпляром после окончания срока хранения. Скрипт проверяет расположение exe и итоговое отсутствие локальных компонентов. Для установки в другом каталоге укажите `-InstallDirectory` и `-DataDirectory`; оба пути должны оканчиваться на `FileStructureAuditor`.

Сертификат удаляется только по явному thumbprint после проверки его остальных применений:

```powershell
.\scripts\Uninstall-Auditor.ps1 -Apply -PurgeData -RemoveCertificate -CertificateThumbprint '<40 hex chars>'
```

Перед удалением сертификата сверяйте его привязки и использование другими службами. Скрипт откажется удалять сертификат, зарегистрированный в HTTP.sys.

## Проверка

Проверьте `Get-Service FileStructureAuditor`, отсутствие `Auditor.Api.exe` и локальных каталогов, целевых firewall rules, открытого Auditor порта и маршрута в Платформе. После удаления DNS имя закрытого экземпляра больше не должно разрешаться. Восстановление возможно из сохранённого release package и backup каталога; для gateway потребуется вернуть конфигурацию и согласованную пару ключей.
