# Корпоративный VPN

Шлюз использует ocserv 1.6.0. Профиль задаёт разрешённые IPv4-подсети. В PL администратор связывает профиль с идентификатором сотрудника и при необходимости задаёт срок доступа. Записи и журнал сохраняются в отдельном томе шлюза.

## Первый запуск и выдача доступа

1. Откройте **Сети → Корпоративный VPN → Шлюз**. Мастер предложит внешний IPv4, локальный адрес для прослушивания и свободную подсеть для клиентов. Можно указать DNS-имя и изменить любой из адресов или портов.
2. Выберите **Встроенный доступ PL** и нажмите **Применить**. PL выпустит сертификат шлюза и создаст удостоверяющий центр для клиентов. В этом же окне можно загрузить свою цепочку TLS и закрытый ключ в PEM.
3. На вкладке **Сети и профили** создайте профиль с корпоративными IPv4-подсетями, доступными этому сотруднику. На вкладке **Сотрудники** нажмите **Выдать доступ**, выберите локального пользователя PL и профиль. Если это первый сотрудник, создайте ему учётную запись в **Настройки → Пользователи**.
4. Откройте карточку сотрудника и скачайте его комплект OpenConnect. Сотрудник также может скачать комплект со своей главной страницы PL. ZIP содержит конфигурацию с адресом и отпечатком шлюза, персональный сертификат, закрытый ключ и инструкцию. Передавайте ZIP конкретному сотруднику по защищённому каналу. Срок сертификата — 30 дней. Пока назначение действует, сотрудник может скачать новый комплект.
5. На устройстве с установленным OpenConnect распакуйте ZIP в личную папку. Из этой папки запустите `sudo openconnect --config pl-vpn.conf` на Linux или macOS. В Windows откройте терминал с правами администратора и выполните `openconnect.exe --config pl-vpn.conf`.

Пул клиентов должен быть отдельным от сетей PL, Docker, локальной инфраструктуры и разрешённых сетей профилей. Если у хоста есть публичный IPv4, PL определяет его по интерфейсам и таблице маршрутизации. За NAT PL запрашивает у ipify внешний IPv4 исходящего соединения по HTTPS. Для входа извне на пограничном маршрутизаторе нужен проброс выбранного внешнего порта TCP и UDP на локальный адрес и порт из мастера. Если оператор использует CGNAT, требуется доступный снаружи адрес или уже настроенный внешний вход. При отсутствии ответа сервиса внешний адрес можно ввести вручную.

После изменения внешнего адреса или ключа TLS выдайте сотрудникам обновлённые параметры. Применение изменений может переподключить активных клиентов. При ошибке применения PL восстанавливает предыдущие настройки шлюза.

## Вход через внешний Dex

Если в организации уже работает Dex, выберите **Внешний Dex**. Укажите его HTTPS issuer, идентификатор клиента и секрет, если он используется. Зарегистрируйте в клиенте Dex точный адрес возврата, показанный мастером. Для частной PKI Dex загрузите сертификат его удостоверяющего центра. Для входа через браузер сертификат шлюза должен быть доверенным на устройствах сотрудников.

Выдайте профиль точному идентификатору `sub` сотрудника из Dex. Администратор может скачать готовый файл `.conf`. Если сотрудник входит в PL через тот же issuer и с тем же `sub`, файл также доступен в личном кабинете. OpenConnect использует адрес и отпечаток из файла и открывает браузер для входа через Dex. Шлюз сверяет подпись ID-токена по ключам провайдера, issuer, audience, срок действия и `nonce`. Для Dex 2.46.1 поддержаны подписанные токены с отсутствующим заголовком `typ`.

## Совместимость с ранее настроенными шлюзами

Существующие шлюзы с операторскими файлами и клиентскими сертификатами продолжают использовать настроенный CA и сопоставление по CN. Перед переходом на встроенную выдачу отзовите старые назначения. После применения создайте назначения локальным сотрудникам и раздайте новые комплекты.

## Доступ к сетям

Шлюз посылает клиенту маршруты его профиля и независимо проверяет пересылаемые пакеты через nftables в собственном сетевом пространстве. Каждая сессия привязана к выданному адресу и TUN-интерфейсу. Разрешённый трафик к корпоративным адресам проходит с подменой исходного адреса шлюзом. Узлу PL нужен собственный маршрут к каждой разрешённой подсети. Доступ к самому VPN-контейнеру, обмен между VPN-клиентами и пересылка IPv6 через туннель закрыты.

Изменение разрешений, отзыв или истечение срока закрывают действующие подключения сотрудника и аннулируют его cookies. Правило nftables с ограниченным сроком перестаёт пропускать пакеты в момент окончания допуска. Администратор также может завершить одну сессию, сохранив назначение для нового входа. При увольнении сотрудника нажмите **Отозвать доступ** в модуле VPN и заблокируйте его учётную запись в настройках PL. Сертификатом для удалённого входа управляет назначение VPN.

Управление выполняет PL через локальный контроллер по ID принадлежащего ему контейнера. Образ включает ocserv, occtl и сведения о соответствующих исходниках в `/usr/share/pl/provenance/ocserv/`.
